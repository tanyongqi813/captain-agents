# ADR-003 — Codex 单负责人与多执行者编排

**状态：** 已决定
**日期：** 2026-10-22

## 决定

派活工作台只把 Codex 作为受信负责人 AI。其他模型只能是执行者或独立审查者，不能决定失败恢复、改写任务边界、换人、拆题、验收或通知主人。

自动流程要近似主人手工在 Codex 和执行 agent 之间复制粘贴：平台把已校验的 Execution Capsule 交给执行者，收回报告、diff、活动与验证证据；Codex 负责人根据受限证据决定通过、增量修正、换人、拆分或求助。

单任务在没有可保留改动或外部副作用时，默认写手回退顺序为 `Kimi → Grok → DeepSeek → Codex`。这只是同一任务失败后的接替顺序，不是新任务初始分配的能力排名。新任务按能力画像、历史证据、成本、期限和可用性选人，所以 DeepSeek 可以直接成为审计、只读分析等任务的首选。

同一项目可以并行执行多个任务，但必须依赖已满足、写入范围不冲突、使用独立副本，且未超过并发和预算授权。同一任务的写手不并行竞赛，回退是串行的。

只有所有允许候选都已失败或被权威拒绝，或无法证明能安全换人，或 Codex 负责人不可用时，整台执行才进入 `needs_owner` 并触发飞书通知。

## 原因

- 规划、复审和上下文连续性需要单一权威来源。
- 执行者之间相互判断恢复策略，不等价于将报告交回 Codex 复审。
- 单任务回退和项目级能力分配是两个独立问题。

## 后果

- 本 ADR 取代 TASK-023 中“负责人可切换为其他 AI”的产品方向。
- 自动故障诊断改为 Codex 负责人的固定复审阶段。
- 需要增加负责人可用性、超时中断、候选台账、能力画像与写集冲突检查。
