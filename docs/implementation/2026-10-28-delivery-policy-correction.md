# 自动推进策略纠正 — 2026-10-28

## 事实与判定

此前把 TASK-031 自动刷新启用授权当作所有后续实现门槛，且把 TASK-018 未执行的桌面验收直接归为等待主人，导致两轮只读检查。该策略撤销，不修改历史报告、不伪造通过状态。

- 开发授权不等于运行授权：可开发默认关闭的自动刷新选项、限频和关闭/撤销机制，用替身验证；不据此开启真实后台请求、读取真实密钥或调用模型。实际开启由主人在产品内显式决定。不再要求主人为继续离线开发重复确认。
- 实施依赖不等于整项验收依赖：已验证的稳定接口可支持独立离线切片；必须明确接口证据、只改白名单、单独复审。不得把未完成任务标 PASSED，也不得将依赖未通过的任务标 READY 或用于自动机器派发。最终集成/发布闸门保持。
- 脏工作区不等于冲突：负责人先核对来源、逐段 diff 与在途活动。仅重叠来源不清/并发修改/操作在途时停止相关文件，不能仅因文件脏就停止所有整合。
- 窗口验收属于负责人责任：先准备/检查离线替身窗口用例，再用具备权限的桌面执行路径验证；若需要工具提权，走明确范围的审批。只有实际被拒、缺失桌面环境或需要真实账户时才请主人行动；未尝试不得说必须主人手工完成。
