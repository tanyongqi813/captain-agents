## 业务结果

检测到持续异常后由独立看管逻辑停止对应执行会话，保存检查点交负责人，避免无限加载和自动重启。

- 不修复 IDE 扩展、不重启 Extension Host、不无限自动重试。
- 不在本轮规划阶段运行收费探测或改实现。

## 架构设计

runner 看管接入纯检测结果；首次进入异常产生一次预警与快照，固定宽限后条件持续才停止。阶段阈值独立于现有 20/5/120 分钟配置，不能借当前 checkBudget 偷改下限。保留日志、候选改动、事件摘要、停止原因与时间；停止仅针对本任务进程树，幂等且在看管异常后仍能清理。回交 existing needs_owner/负责人入口，自动续跑和换人不在本任务实现；不能因为错误日志增长取消预警，只有有证据的新有效进展才解除。先写入已有可表达字段，新增持久字段确有必要时兼容迁移在 Capsule 明列。

## 兼容要求

- 既有隔离、凭据、网络和预算边界保持；执行与 IDE 的进程证据分开。
- 历史记录未采集字段显示未知，不补零。

## 验收标准

1. 替身证明错误日志持续增长仍能按确认阈值停机；正常读取和长运行工具不误杀。
2. 停止后改动和证据保留，且不重启 IDE、不自动再派收费任务，不影响其他 job。
3. 停止请求重复、睡眠、看管崩溃、进程已退出均有定向覆盖，原因码可区分三类异常。
