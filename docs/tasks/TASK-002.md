## 业务结果

设置页新增“项目”分页。主人点击“添加项目”，通过原生目录选择器选择仓库，确认项目标识与显示名称后完成登记；登记结果、快速体检结果和错误均以中文展示，成功后项目立即出现在新建群聊的项目下拉框。

## 范围

- 包含：更新 UI 规范、设置侧栏“项目”、项目列表、空状态、“添加项目”流程、名称确认、登记中/失败/成功状态、快速体检摘要、UI 测试。
- 不包含：高级 setup/verify/deny-read/rules 编辑、删除登记、归档管理、完整体检；这些进入 TASK-003。

## 现状与设计

- 设置使用 `SideNavLayout`、`SettingGroup`、`SettingRow`；新页面必须复用这些统一部件。
- `View.projects` 已能提供项目名、显示名和归档状态。登记操作使用 TASK-001 的专用桥，不直接读取或写入路径。
- “添加项目”按钮先触发原生选择；取消保持原页面不提示错误。选择成功后打开窄确认弹窗：只显示仓库路径（不可编辑）、项目标识、显示名称；项目标识写清“用于命令和登记，登记后本阶段不支持修改”。
- 成功后关闭确认弹窗、显示成功提示，并等待后台发布的新 View 更新列表；快速体检失败显示警告但仍明确“项目已登记”。
- 项目列表至少显示：显示名称、项目标识、仓库路径、归档状态。长路径截断并提供完整 title。

## 约束

- 遵守 `AGENTS.md`；先改 UI 规范再改界面，不新增依赖。
- 不自己画弹窗、按钮、下拉框；复用 `Modal`、`Button`、`SettingGroup`、`SettingRow`。
- 所有错误都显示后台返回的中文原因；路径只当纯文字显示。
- 浅色、深色、窄窗口和双层弹窗均需负责人截图检查。
- 不自动创建群聊、不自动派活；登记只是让项目进入可选名单。

## 验收标准

1. 设置侧栏出现“项目”，空状态能清楚说明尚未登记并提供“添加项目”。
2. 原生选择取消无副作用；非 Git 目录显示中文错误。
3. 确认弹窗可编辑项目标识与显示名称，但不可编辑仓库路径；非法、重复名称不能登记。
4. 成功后列表更新，新建群聊无需重启即可选择该项目。
5. 快速体检失败时仍显示项目已登记，并给出后续可重新检查的说明。
