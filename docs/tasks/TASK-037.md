## 业务结果

区分日志活跃和有效进展，检测首事件等待、工具未结束及重复读取，防止错误输出无限刷新停滞计时。

## 非目标

- 不修复 IDE 扩展、不重启 Extension Host、不无限自动重试。
- 不在本轮规划阶段运行收费探测或改实现。

## 架构设计

基于真实结构化事件建立有界观察状态：首个有效事件、按调用 ID 配对的工具开始/完成、路径和操作的脱敏指纹、错误/重连计数与有效进展时间。完成读取不代表实现进展；重复读取是预警证据，不仅凭读次数直接强停。支持并行工具、重复事件、分块 JSON 和未知协议；未知保留未知，禁止猜测。初始候选首事件 90 秒、读取未结束 180 秒、同一读指纹 5 分钟内 5 次仅作为待校准默认，正式强停阈值由探测证据确认。新增纯函数判定接口和时钟注入，不改变其他通道语义。

## 兼容要求

- 既有隔离、凭据、网络和预算边界保持；执行与 IDE 的进程证据分开。
- 历史记录未采集字段显示未知，不补零。

## 验收标准

1. 离线测试覆盖无限错误日志、重复读同文件、并行正常读取、真实新进展和正常长命令，不将它们混为同一类。
2. 只有日志字节增长或 mtime 更新不能重置新增有效进展计时；总时限仍保留。
3. 时间窗口与事件缓存有界，休眠扣除，缺失调用 ID 不编造配对。
