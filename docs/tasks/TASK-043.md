# TASK-043 — 前置解除后的自动规划与激活

- handoff_contract: `1`
- status: `DRAFT`
- priority: `P1`
- difficulty: `High`
- dependencies: `TASK-045[PASSED|PASSED_WITH_NOTES], TASK-046[PASSED|PASSED_WITH_NOTES]`
- current_attempt: `none`

## 业务结果
在主人完成一次项目级无人值守授权后，前置全部通过的 DRAFT 任务由负责人自动检查信息完整性；能从可信事实唯一确定边界时生成首轮 Capsule、领取并进入授权队列，前一任务验收通过后可自动提升下一项，不要求逐轮点击。

## 非目标
- 不从空白或“待确认”内容猜测文件、命令、权限、基线或产品决策。
- 不代替主人授予联网、凭据、破坏性操作或无限预算。

## 架构设计
规划扫描只在持久化授权范围内选择一项：先按 P0→P3，再按台账顺序；同时检查写集冲突、并发上限、费用/调用/时间预算、项目归档状态、Git 基准、联网与凭据要求和执行能力。负责人只能从 Task Spec、仓库代码和既有验证事实生成候选；平台校验指纹、锚点、白名单、验证、基线和预算后，复用 TASK-028 的事务与租约入口。通过验收时由同一状态机关闭 Capsule、追加 Review Record、将 Task 标为 PASSED/PASSED_WITH_NOTES，再选择下一项。

## 兼容要求
- 旧项目和未启用项目保持现状；授权可随时暂停。配置缺失或多项同级没有确定顺序时保持 DRAFT 并说明缺口。

## 验收标准
1. 一次性授权明确项目、分支/规划基准、最大并发、费用/调用/时间上限、联网和允许自动提交的路径；自动运行期间无需逐轮点击。
2. 前置通过且事实齐全时自动生成、领取并派发首轮 Capsule；通过后自动关闭审计链并提升唯一下一项。
3. 任意待确认锚点、白名单、验证命令、基线、权限、冲突或无确定顺序时不自动激活。
4. 暂时限流、执行器退出和会话丢失按有界策略自动退避或换新执行器，不因纯运行故障立即求助。
5. 崩溃重启不重复创建 attempt、重复派发或扩大授权范围。

## 依赖与排序
- TASK-045/046 先分别完成单任务返工和拆分子任务闭环；本任务最后接入自动队列。

## 主要接口
- `src/core/task-plan.ts` — 依赖已解除但仍为 DRAFT 的候选投影。
- `src/core/autopilot-engine.ts` — 负责人规划动作与恢复。
- `src/core/lead-capsule.ts` — 首轮 Capsule 的事务发布与领取。
- `src/core/settings.ts` — 项目级无人值守授权和预算范围。

## 长期约束
- 同一时刻只自动激活授权队列中唯一的下一项；需求含糊不得以默认值掩盖。
- 主人确认的是项目级边界而非每轮执行；权限、凭据、不可逆副作用、预算或数据完整性异常仍是硬停止。
