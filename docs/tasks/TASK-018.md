# TASK-018：设置成本资料与额度未知时的预算

- 状态：`DRAFT`
- 优先级：`P2`
- 难度等级：`High`
- 前置任务：`TASK-017` 评审为 `PASSED` 或 `PASSED_WITH_NOTES`
- 需求来源：无法正常查询额度或使用中转站时，主人需要提供有效的计价依据与本地消耗上限。

## 业务结果

主人可在设置中维护预算账户、人工余额与价格、经验参考；额度未知时仍能在明确的本地预算内工作，付费接入不会作为无限兜底。

## 范围

- 包含：界面规范、成本资料编辑与来源时间、账户/模型绑定、共享账户的每日时长/尝试数/并发上限、专用设置桥与派发/续跑预算校验。
- 不包含：新增登录密钥、中转站网络查询、跨客户端全局费用保证、硬性金额结算限额、运行中的自动模型切换。

## 现状与设计

- 先更新 `docs/ui-spec.md`，设置使用统一部件，清楚分开“服务端额度”“主人填写的数据”和“工作台本地预算”。不把手动余额标为已验证，不把本地上限写成账户实际剩余量。
- 复用 TASK-017 的非敏感契约，界面只提交允许字段，后台重验通道、账户、类型/长度、非负数、计价版本及来源时间；不接受任意 URL、密钥或网络请求参数。
- 额度未知且已授权使用的接入，派发与续跑按主人设置的账户级每日累计执行时长、尝试数和同时运行数受控使用。无配置时由负责人明确说明未知并等待主人设置，不能默认为无限或零；原有全局并发及执行预算继续生效。
- 每日按主人的本地日期记账（记录日期和时区，默认客户端时区），账户锁内检查并预占一次尝试和并发位，再启动；启动失败释放并发位，确实进入模型尝试才计尝试，保留失败证据。时长预算不足时将单次剩余时限收窄，暂停/重启后不重置已耗预算；复用现有进程有界收尾能力。
- 服务端明确触顶仍拒绝；未知不能掩盖触顶。手动余额仅供规划，金额估算不完整时不声称能保证不超支；需要硬性费用限额应由付款服务账户侧控制。
- 第一版只维护一个共享资料源，不读取账单网页或引入新网络例外。保存失败保留原设置，并发保存不覆盖其他设置。

## 约束

- 遵守 `AGENTS.md`；不新增依赖，不放宽选手策略、隔离或全局预算。
- 选手与模型输出不能修改预算；普通项目题目也不能覆盖账户绑定或价格资料。
- 本地预算先原子预占再启动，超限检查不能仅在 UI 执行；新启动与续跑遵守相同规则。

## 验收标准

1. 主人能保存价格、币种、生效时间、人工余额与经验，窗口明确显示来源和过期状态；非法或并发提交不留下半份配置。
2. 同账户两个模型同时派发不能突破共享次数/并发预算；换模型不归零，重启与跨日按记录规则计算。
3. 无法查额度但具备本地预算的接入可有限使用；未设预算、额度明确触顶或本地预算用尽时给出可处理原因，不擅自开启付费兜底。
4. 每日时长上限收窄单次执行时限并可靠回收进程；启动失败、续跑和重启不泄漏并发占位、不漏记已耗成本。
5. 浅色、深色、窄窗口及编辑状态截图验收；离线替身测试覆盖设置、并发启动、限额拒绝和续跑。
