# TASK-017：完成成本账本与中转站计价依据

- 状态：`READY`
- 优先级：`P2`
- 难度等级：`High`
- 前置任务：无，复用当前任务、历轮 usage 与自治执行关联
- 需求来源：按达标总成本安排派活；兼容额度查不到、中转站及人工成本经验。

## 业务结果

负责人能看到一件任务从首次实现到失败、返工、复审和换人交接的整体消耗，以及数据的来源与缺项；可区分低价多轮和高价一次达标，而非只比较单次报价。

## 范围

- 包含：本地成本与预算资料的数据契约、关联任务/尝试的只读成本账本、已知账单/usage 与人工价格的计算、人工经验参考、数据来源/可信度、旧记录兼容。
- 不包含：中转站网络查询、读取新密钥、爬取账单、自动汇率、自动派活、真实花费保证、设置页（TASK-018）。

## 现状与设计

- `src/core/job.ts` 已有 usage 和历轮记录；`src/core/endpoint.ts` 与 `deepseek-settings.ts` 区分接入配置，但不能仅凭模型或域名证明真实付款账户及共享预算。
- 定义主人配置的非敏感预算账户标识，绑定通道/模型到预算账户及独立额度池。模型来源继续由 roster 派生；同一中转站不同付款账户不能误合并，同账户多个模型不能重复计算余额。账本不保存带凭据的 URL。
- 数据契约区分官方订阅窗口、按量收费、次数/套餐和本地执行预算，分别保存金额/币种、token、次数和时长，禁止跨单位直接相加。手动余额、价格和成本经验必须有来源时间和适用范围，未知字段不补零；有效时间过后显示过期。
- 计价资料采用带生效时间的版本快照。明确识别输入、输出、缓存等已有 usage 字段及其重叠含义，避免缓存重复计费；无法匹配价格维度、缺 usage、单位不同或价格不适用时只能列出已知小计和未知项。价格变更不重算为历史实际账单。
- 若已有可信费用字段则保留实际费用；否则只能按主人提供的适用价格估算。估算不称实际扣费；没有用量时可附主人经验区间/相对参考，但不生成精确金额。
- 原 Task/自治执行 → 任务号 → 尝试/轮次形成稳定关联，归集初次实现、失败、重试、复审、诊断和交接。优先读当前权威任务记录，不复制一个可漂移的完整任务状态机。稳定 ID 去重，跨角色共享的同一次调用只计费一次。
- 无关联的负责人调用、其他客户端消费或账单缺项列为“不完整”，不能宣称已经覆盖全部费用。并发额度快照差值只能作为共享观察值，不能平摊成精确任务费用。
- 未达标或取消的任务保留成本，不能只统计成功样本。下一步选择可比较预计剩余成本，历史已耗成本单独保留，避免沉没成本驱动无限返工。
- Kimi 官方 `/usage` 已确认，实际安全采集由独立 TASK-019 实施；本任务不以它为前置。接入后套餐窗口、会话用量和 Extra Usage 元数据分别消费；加油包全账户余额及月消耗不能充当某件任务的实际扣费，中转账号也不能套官方套餐。
- 暴露纯函数和受校验的资料读写接口，供 TASK-015/016/018 使用；资料锁内读改写、临时文件改名，修改资料不覆盖原始 usage。现有记录缺字段按未知展示。

## 约束

- 遵守 `AGENTS.md`，不新增依赖，不触发网络或 AI 调用。
- 不将官方订阅百分比、中转站货币与本地时长伪造为可直接比较的统一分数。
- 数据必须有出处和完整性标志；人工经验不硬编码为供应商性能或价格事实。

## 验收标准

1. 三轮实现加一次审查与一次失败后换人的成本均可归集；重读、重复关联和跨角色引用不重复计费。
2. 同币种、字段完整的估算可复算；缓存语义不明、缺用量、价格过期、跨币种、跨套餐均保留未知项，已知小计不冒充总成本。
3. 同账户多模型共享预算、不同账户不合并；订阅额度与按量费用分别展示，不能套用原厂额度。
4. 人工记录“某类任务 A 多轮仍约 B 的三分之一”可保存、修改和注明时间范围；不因此启动验证任务或生成实际扣费。
5. 旧记录、外部负责人费用未知、取消与失败记录均可读取；账户资料修改原子化且不改写历史 usage。
