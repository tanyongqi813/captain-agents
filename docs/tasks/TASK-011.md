# TASK-011 — 安全细拆、专用副本与自动验收闭环

## 业务结果

当负责人 AI 返回受控子任务图时，平台可在一个专用副本中串行执行，每步独立审查，失败可回到上一个已接受快照，全部完成后运行项目已登记的验收命令，形成可采用结果而不自动合并主分支。

## 范围

- 包含：子任务图的严格校验/持久化，专用副本，受控串行写入，累积补丁快照/回滚，独立只读审查，有界返工，项目登记验收，最终证据包。
- 不包含：并行写子任务、AI 生成验收命令、修改项目 Task Spec/状态、自动合并/提交/push、桌面界面。

## 现状与设计

- `split` 候选图必须是有向无环图，节点只有编号、标题、目标、验收文本和依赖。节点数、深度、字段长度、总尝试和整体时长受启动时策略限制。
- 平台为每次自治执行建一个可验证的专用 worktree/分支，路径由核心根据登记 ID 计算，不接受 AI/UI 输入。任何时候只有一个写手在其中运行。
- 每个节点从“起点 + 已接受累积补丁”开始。写手结束后保存候选 diff，同步到独立只读审查副本，复用现有小队的审改报告协议；通过才更新累积补丁快照。
- 回滚只操作该自治执行的专用副本：复位到登记起点后重新应用已接受累积补丁。不操作主工作区，不用 stash，不接受外部路径。
- 每个节点的审查返工与诊断恢复都受预算限制。全图通过后只调用项目登记的 `verify` 命令和 `verifyTimeoutMinutes`；验收不过回诊断，预算用完转 `needs_owner`。
- 自治执行 `completed` 表示有通过的独立审查、最终验收与完整补丁证据；不表示已自动合并主分支或篡改 Task Spec。
- 为兼容旧登记，闭环仅在主人明确选择独立审查者时开启：CLI `autopilot start … --who 执行者:强度 --reviewer 审查者:强度`，此时只允许一位可写执行者、另一位只读审查者。没有该选择的旧流程保持交给主人、不自动接受成果；TASK-012 再接显式选择界面。

## 约束

- 遵守 `AGENTS.md` 和 ADR-001；不新增依赖。
- 清理/回滚前必须用已登记的 repo、base、worktree 路径、分支名和 `realpath`/Git 信息多重核对；不得对主工作区执行破坏性 Git 命令。
- 不执行 AI 输出里的任意命令。项目验收只读登记处，仍走现有验收超时和进程树收尾。
- 自动流程不得为了继续而跳过选手策略、额度、隔离、登录、并发或 DeepSeek 闲时检查。
- 初版严格串行；不做写集猜测或并行合并。

## 验收标准

1. 合法子任务图能按依赖稳定排序；循环、缺依赖、重号、超限或夹带命令/路径/权限的图在副作用前被拒绝。
2. 两个写节点在同一专用副本中串行累积；第二节点能看到第一节点已接受改动，主工作区不被修改。
3. 节点审查不过后可在上限内返工；返工仍不过或预算用完时转 `needs_owner`，不跳过审查接受 diff。
4. 在候选改动中断、审查崩溃和快照写入中断后重启，能从最后已接受补丁重建副本，不丢已接受改动、不重复执行节点。
5. 全部节点通过后运行且只运行登记验收命令；全通过才转 `completed`，失败进诊断且仍受总预算限制。
6. 完成记录能追溯原 Task ID、每个节点、每次尝试、审查结论、验收结果和最终补丁；主分支和 Task Spec 未被自动修改。

## 实施报告

- 新增 autopilot-worktree.ts：核心计算写手/审查专用路径与分支，多重 Git/realpath/HEAD 复核；SHA-256 内容寻址的累积补丁、接受前候选、逐次尝试补丁引用；回滚只清理已核对的本台专用副本，先保全原候选，再重建已接受快照。台账/spec 改动拒绝接受。
- 新增 autopilot-flow.ts：固定角色串行派发；独立只读审查沿用小队报告协议，有必须改意见不能靠“通过”字样放行；一次有界返工，未知报告/崩溃/快照不符求助。审查计入 AI 总预算、逐轮记用量。DAG 节点继承主人的选择与权限，图校验、全局编号、依赖与父深度受硬限约束。
- 最后仅运行项目登记 verify/verifyTimeoutMinutes，并受剩余总时长、项目验收锁和进程树超时收尾约束；无登记命令不宣告完成，验收失败进诊断。验收中断重启保守求助，避免重复可能有副作用的验收命令。准备、验收时间均入预算，不将长命令误判为休眠。
- dispatcher 只增加可信内部角色入口，不接受外部路径，复用全部策略、额度、登录、平台隔离、并发和 DeepSeek 闲时闸门；复用副本必须同一登记/动作令牌/起点/权限且单飞。普通任务清理不删除自治共用副本；推进期间不得单独清理、采用或验收节点，外部合并后的采用需要提供真实提交号。
- 测试新增 16 项真实 Git + 替身选手用例，覆盖两节点累积、只读审查/返工、全部通过再验收、坏快照/伪造路径、崩溃认领、晚改动、预算边界和管理动作保护。整链演练通过：正常派发后注入已收尾的 stalled 任务结果 → 真实只读诊断返回 split → 两节点 → 一次审查返工 → 登记验收；不是等待真实 10 分钟停滞，也未调用真实模型。
- 验证：完整 npm run verify 通过：核心 950 项（940 通过、10 平台跳过）、界面 318/318、构建、真实 Electron 冒烟 1/1。随后加强审查报告大小/普通文件检查和恢复阶段显示，typecheck 与新增 16 项重跑通过，构建再验；最终整合批次仍会再跑整库。
- 文件涉及核心登记/推进、两个新模块、可信 dispatch 入口、共享副本保护及 CLI 参数，附类型、夹具和回归。未改模型启动参数、隔离模板、原作者主分支、项目台账状态或工作区；专用副本/分支保留供主人采用，不自动合并/提交/push 用户项目。
