## 业务结果

执行者长时没有可验证进展或超过本轮上限时，平台主动中断并保留现场，再由负责人给出更明确的增量提示词、拆题、换人或求助决定。

## 非目标

- 不把单条命令暂无输出等同于停滞。
- 不在中断后删除副本、日志或部分改动。
- 不无界续跑同一会话。

## 架构设计

停滞判定同时考虑最后活动、副本变化、子进程存活、已知长命令阶段和睡眠扣除，使用预设而非任意时间。先记录中断意图和令牌，再终止进程树，最后收集证据交负责人。任何重启前都重新校验改动、依赖、额度和预算。

## 兼容要求

- 沿用 TASK-008 的预算、停滞和收尾证据，保留 `stalled` / `timed_out` 历史语义。
- 外部取消、主人手动停止和自动停滞中断必须可区分。

## 验收标准

1. 正常长命命令、电脑休眠和副本持续变化不会被误杀。
2. 超时时只中断对应任务的受控进程树，不影响并行任务。
3. 中断后的报告、diff、日志尾、活动、验证和改动数一次性交给负责人。
4. 负责人修正或拆分只产生新的增量 Capsule，包含窄边界、验收切片和单轮预算。
5. 相同证据和方案不重复执行；剩余预算不足则求助。

## 依赖与排序

- TASK-027 先建立唯一负责人复审环。

## 主要接口

- `src/core/runner.ts` — 停滞与本轮超时终止原因。
- `src/core/autopilot-engine.ts` — 中断证据交接和重规划。
- `src/core/autopilot-diagnosis.ts` — 中断证据和恢复动作校验。

## 长期约束

- 中断必须幂等、可恢复，不把未知状态记成已安全停止。
- 已有改动或外部副作用不明时，保留现场并禁止无条件换人。
