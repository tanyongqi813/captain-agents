# TASK-016：正常复审沉淀评分与难度证据

- 状态：`DRAFT`
- 优先级：`P2`
- 难度等级：`High`
- 前置任务：`TASK-011`、`TASK-017` 评审为 `PASSED` 或 `PASSED_WITH_NOTES`
- 需求来源：负责人在正常派活、复审中积累评分，作为合理分工的依据，避免额外试题消耗。

## 业务结果

一件任务由一家完成也能形成带证据的评价；负责人能区分困难实现、普通实现与只读审查的表现，不把总平均分当成绝对能力排名。

## 范围

- 包含：派活上下文与复审证据记录、复用既有 `rate` 存储、待评价状态、幂等补评、按角色/难度筛选证据和旧记录兼容。
- 不包含：额外模型评分调用、重复派题、未经主人确认的自动换人、推翻已有评价或篡改旧任务难度。

## 现状与设计

- `src/core/rate.ts` 已支持负责人给结束任务打分、外部原因及改分历史；`profiles.ts` 当前按选手 × 类型 × 快速版分组。保留已有 1–5 分含义，不另建评分表。
- 新增有界评价上下文：写手/审查角色、来源 Task/节点、派活时难度（Low/Medium/High/未知）与来源、复审/验收证据引用。未知难度保留未知，不按供应商、用时或分数倒推。
- 正常复审的同一次结果可携带可选评价建议；平台只接受严格字段并核对任务、节点、尝试和现有证据。沿用现有 `rate` 写入路径，初次评价按稳定的复审结果 ID 幂等，重放不生成多版评分；明确修改仍保留历史。
- 评价基于实际缺陷、返工、验收和报告真实性。评分不是审查通过的替代品；成功采用不自动等于 5 分。审查任务依据有效发现、误报与经核查的遗漏评判，不因没人独立核查就宣称“无遗漏”。
- 评价分开保留质量证据、返工次数、实际用时与 TASK-017 的完成成本引用，不合成未经解释的性价比分，也不修改已有 1–5 分标准。低价选手多次返工可能质量分较低、总成本却更优；负责人可据此选择，而不是按平均分排序。
- 按原 Task/自治执行归集历次尝试，失败、换人和审查消耗不能从成本样本中剔除；复审与实现的评分角色分开，流程总成本引用同一份账本，不重复记费。未知成本和外部故障明确保留，不能作为零成本优秀样本。
- 没有负责人结论或额度不足时只记录待评价；停止、保存证据和 `needs_owner` 通知照常完成。评价字段无效时保留有效复审结论、记录待评价，不另启动 AI 修复格式。
- 普通命令行任务仍由负责人在现有复审后调用 `rate`；无人看守接线消费 TASK-011 的已有复审结果，不增加模型轮次。只读汇总支持相近难度与角色的样本过滤，旧汇总调用和旧记录展示保持兼容；不覆盖旧分数。

## 主要文件

- `src/core/autopilot-engine.ts`（消费既有复审结果）
- `src/core/profiles.ts`（按角色/难度过滤证据）
- 必要类型：`src/core/job.ts`；测试：`test/rate.test.ts`、`test/profiles.test.ts`、`test/autopilot-engine.test.ts`

## 约束

- 遵守 `AGENTS.md`；不新增依赖，不增加 AI 尝试或自动试跑。
- 派活时上下文必须来自权威 Task/节点/策略；AI 自报和项目文本不能变成修改配置的授权。
- 评分落盘失败只影响评价状态，不能回滚已完成验收或触发重新实现。

## 验收标准

1. 单家正常执行、复审与评分完整可追溯，AI 尝试数与不评分时一致。
2. 同一复审结果重复消费只落一次评分；中断后能补评，不重复启动选手，明确改分仍保留旧版。
3. 外部故障、证据不足、负责人额度耗尽、非法评分和存储失败都能保留待评价，任务收尾及求助通知不受阻。
4. 写手/审查与难度样本可分开查询，旧记录按未知处理，不伪造分类、不改历史平均分口径；样本少明确提示。
5. 建议的分数和证据引用不匹配时拒绝评价，不把“测试通过/采用”直接映射为高分。
6. 同一达标任务可同时呈现“多次返工、质量分较低、总成本更低”；失败后换人、共享一次审查及缺失用量的样本不会漏算、重复记账或被标为零成本。
