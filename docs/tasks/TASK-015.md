## 业务结果

负责人以达到验收要求为门槛，优先比较完成整件任务的预计总成本，再结合期限，最后核对剩余额度和预算可用性。低价选手即使需要多轮返工，只要最终合格且全流程成本更低，仍可优先；不因另一家单次评分更高或余额更多就持续派给它。

## 范围

- 包含：只读派活参考生成器、TASK-017 的完成成本证据、期限、相关额度池与多窗口约束、数据时间/未知状态、在途负担、样本置信说明，以及指挥手册实时附录的接入。
- 不包含：自动选手派发、强制轮转、跨账号额度换算、付费接口自动兜底、运行中换人、为了学习或评分增加试跑。

## 现状与设计

- `roster.ts` 保存通道与 Cursor 池映射，`quota.ts` 提供窗口、用量、重置时间和数据时间；`profiles.ts` 当前按选手、任务类型、快速版汇总，尚无难度/角色的可靠分组。
- `stats.ts` 的历史消耗口径与现有快照结构须核对：不能直接把缺字段或不可比的快照差值当成单任务成本；并发快照可能包含同池其他任务消耗，最多标为共享观察值。
- 决策顺序固定为“预计可达标 → 完成总成本 → 期限 → 剩余额度/预算可用性”；已触顶、超预算、禁用和不满足隔离条件仍在派发前拒绝。最后考虑额度表示不把余额高作为首选理由，不表示可以先启动再检查。
- 消费 TASK-017 的成本证据，比较初次实现、历次失败/返工、复审、负责人诊断和换人交接的合计，不能仅比较单次价格或成功尝试。优先使用同类型、相近难度、同角色流程的正常任务样本；难度字段尚缺时明确降低可信度，不倒推分类。
- 实际费用、按价格估算、主人经验和未知分别标识；不同货币/计量单位无明确换算依据时不生成价格排名。已支付订阅的额度消耗单独展示，不擅自将月费除以百分比当边际费用；付费调用不因订阅触顶而自动启用。
- 主人关于“DS 多轮修改仍约为 Cursor 三分之一”的经验以可修改的人工参考保存，注明适用范围与记录时间；不硬编码供应商倍率，也不为验证倍率增加试跑。
- 初版不捏造成功概率或精确预算预测；有有效样本时展示成本区间、样本数和缺项；只有人工参考或无可比数据时提供条件建议并由负责人判断。
- 每次续跑/换人比较从现在起的预计剩余成本与时间，既保留已耗成本，又不因沉没成本继续投入。节点无实质进展、到达既有次数/时长上限或预估剩余方案不划算时建议升级、等待或求助，不无限重试；参考本身不自动换人。
- 新增纯函数，根据权威快照形成每位选手的参考项：可用性、相关共享池、所有相关窗口、数据时间、到停派线余量、已知重置时间、在途数量、相近类型表现样本和不确定性。不新增第二张模型/池清单，映射从 roster 派生。
- 多窗口逐一保留；五小时窗口耗尽但周窗口有剩余时不能当成可派。数据陈旧按现有额度模块的有效期判断；未知不是零消耗或无限余额。
- 同池多模型共享负担；负责人自己的消耗可能不在工作台任务账本中，因此服务器快照优先。不同厂家 20% 不能当作相同工作量，重置日未知不推算月底余额。
- 能力证据不够时明确“样本不足，需负责人判断”，不得仅按最低用量推荐。高难任务缺少合适候选时返回等待/求助建议，不降低验收要求。给恢复和审查留量属于负责人的规划理由，不私自新增硬停派线。
- 接入 `guideAppendix()`，只展示事实和选择依据，不修改当前选手、预算或派活规则。复用现有数据读取，不为生成参考启动 AI 或额外查询进程。

## 验收标准

1. 同池两个模型共享负担，独立池不合并；短窗口触顶时不能因为长窗口宽裕而显示可派。
2. 额度陈旧、查不到、重置时间未知、快照跨重置和并发消耗都明确标不确定，不能生成虚假的精确成本或耗尽日期。
3. 在合成样本中，A 经三轮修改达标的完整成本为 3 个同币种单位、B 一次达标成本为 9 个单位且均满足期限时，优先建议 A；不能因为 B 返工少或分数更高而反选。单位和倍率仅用于测试，不对应固定供应商。
4. 候选同时展示成本依据、期限、额度、在途负担与重置时间；低价选手不达标、超时、预算不够或无进展时不再盲目推荐。没有合适候选时建议等待或求助。
5. 手册输出只读、不起 AI、不创建任务或副本；现有 quota、guide、派发测试保持通过。
6. 官方额度、手动预算和中转站费用数据分别处理；未知价格/余额不按零或无限处理。失败后换人仍计入完整成本，推荐下一步只比较剩余方案，且不越过原有恢复预算。
