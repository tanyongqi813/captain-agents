## 业务结果

负责人修正和拆分提案经平台编译成结构校验通过的增量 Capsule，继承原执行范围，不用自由提示词续派。

## 非目标

- 不写规划或运行登记、不启动模型、不自动接受成果、不提交代码。
- 不选择负责人或执行者，不接界面，不迁移旧自治状态。

## 架构设计

纯函数接收真实任务文档快照、原胶囊指针、候选版本、负责人原始回包和平台分配的 finding 编号。先用现有共享契约验证文档与依赖，再用负责人协议校验回包绑定；平台分配新 attempt，继承原锚点、修改白名单、非目标、验证和预算，仅改本轮目标、验收和当前 findings。提案正文逐行引用，不能伪造元数据或章节。拆分整组编译及验证全部成功后一次返回；仅产生待持久化制品，不更新 TASK_LIST 指针或执行。

## 兼容要求

- 共用 assembleHandoff，不重写七列台账、任务依赖与交叉引用规则。
- 保留旧胶囊与 Review Record，不复用已有 attempt，不覆盖历史。

## 验收标准

1. correct 与 split 可生成完整增量胶囊；每份经共享契约及源码锚点文字规则校验。
2. 文件白名单、锚点、验证、禁止项、预算和停止条件原样继承，不能由模型扩权。
3. 未通过前置、过期候选/胶囊、缺 finding、冲突编号、非法提案或任一子节点失败时整组拒绝。
4. 模型文本不能注入元数据或额外章节，不把完整 Task Spec、旧审查历史或聊天发送给执行者。
5. 输入不变，无读写/启动副作用；生成物仍需运行侧原子持久化和资格核验。

## 依赖与排序
