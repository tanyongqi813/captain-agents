# TASK-014：设置页接入飞书机器人

- 状态：`PASSED`
- 优先级：`P2`
- 难度等级：`High`
- 前置任务：`TASK-013` 评审为 `PASSED` 或 `PASSED_WITH_NOTES`
- 需求来源：主人需要在设置中安全连接飞书机器人、确认连接可用，并看到通知投递是否异常。

## 业务结果

主人可在设置页连接或断开一个飞书群自定义机器人，发送测试通知，并看见最近一次成功或脱敏失败状态；窗口和普通配置始终读不到已保存的敏感凭据。

## 范围

- 包含：先更新界面规范；设置分页/分组；Webhook URL 与可选签名密钥的一次性写入；连接、替换、测试、断开；脱敏状态；主进程/preload 白名单桥；凭据存储适配；界面、主进程和真窗口测试。
- 不包含：读回或展示完整凭据、任意 Webhook、多个通知目的地、飞书回复/按钮、企业应用机器人私聊、通知正文自定义模板。

## 现状与设计

- 设置新增“通知”分页：保留系统通知开关，并增加“飞书机器人”分组。未连接时说明第一版发送到机器人所在群；主人若只想自己收到，可使用只有自己和机器人的群。
- 输入只在连接/替换弹窗中存在：Webhook URL、可选签名密钥。保存成功立即清空组件状态；再次打开只显示“已连接”和脱敏标识，不把旧值送回窗口。
- 窗口只可调用 `feishuConnect({ webhook, secret? })`、`feishuTest()`、`feishuDisconnect()`；后台重新校验字段数量、长度、HTTPS、官方主机和路径。测试消息使用固定文字和随机测试事件号。
- 凭据使用操作系统保护的存储能力；`config.json` 只保存非敏感开关和脱敏元数据。凭据不可用或解密失败时按未连接处理并给出可操作提示，不删除待发事件。
- 断开必须二次确认；只删除飞书凭据和连接元数据，不删除应用内历史与通知事件账本。之后重新连接可发送仍有效且未被主人处理的待发事件。
- 设置显示：连接状态、最近成功时间、待发数量、最近一次脱敏错误和“发送测试通知”。不展示响应原文、token、secret、请求签名或绝对路径。

## 约束

- 遵守 `AGENTS.md` 与 ADR-003；不新增依赖，先改界面规范。
- 主进程校验可信窗口和严格白名单；普通 `setSettings` 不得写入、覆盖或删除飞书凭据。
- 凭据不得出现在 View、错误提示、测试快照、日志、崩溃报告、诊断包或剪贴板。
- 保存/替换凭据与连接元数据要么都成功，要么保留旧连接；并发保存与测试串行化。
- UI 全中文，使用已有统一部件；失败原因只写主人能处理的脱敏结论。

## 验收标准

1. 合法连接可保存并发送固定测试通知；重启后仍显示已连接且能发送，窗口侧从未收到完整 Webhook 或签名密钥。
2. HTTP、非飞书官方主机、错误路径、控制字符、超长值和额外字段均被后台拒绝；错误文字不回显敏感值。
3. 保存中重复点击、测试与替换并发、凭据保存失败均不产生半连接状态；旧连接在替换失败后仍可用。
4. 断开经二次确认，删除凭据但保留通知历史和待发事件；重新连接后只补发仍有效、未处理的事件。
5. 设置页可见最近成功、待发数和最近脱敏错误；测试失败不影响系统通知，也不生成新的 `needs_owner` 事件。
6. 浅色、深色、窄窗口和连接/断开弹窗截图通过；真窗口冒烟覆盖连接替身、测试、重启保留状态和断开。
